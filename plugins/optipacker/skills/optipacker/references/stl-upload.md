# STL attachment transfer

This flow needs `models:write`, file/code tools with access to the attachment and outbound HTTPS access to the returned storage URL. If transfer is unavailable, use the OptiPacker website upload and resume from the saved part ID.

1. Resolve the project and get the intended part name. Ask for the source units (`mm`, `cm`, `m` or `in`) and measured weight in g. STL has no units, material, measured mass or part price.
2. Call `list_materials` for the project, optionally with a material search and `measuredWeightG`. Show relevant returned material names, IDs and recorded prices. Follow `nextCursor` as `afterId` when more options are needed. Ask the member to choose one. If the required material is absent, use the website to add it before importing.
3. Require a cost choice. Offer **Enter part price** (amount and currency) or **Use raw-material estimate** (show the returned USD amount and explain that manufacturing is excluded). The member must accept the estimate. A missing estimate requires a manual price. An explicit zero is valid; missing is not zero. Only USD or the organization's currency with an available supported rate can be converted. For another currency ask for a USD amount.
4. Run `python scripts/upload_stl.py inspect /absolute/path/part.stl` from this skill folder. It reports `originalFileName`, `byteLength` and `sha256`.
5. Call `prepare_stl_upload` with those file facts, `projectId`, `name`, `sourceLengthUnit`, `measuredWeightG`, the chosen `materialId` and `materialRevision`, `partCost`, and `idempotencyKey`. Manual cost uses `{ "source": "manual", "value": 2.5, "unit": "usd" }`. An accepted estimate uses `{ "source": "estimated", "acceptedUsdValue": <returned amount> }`. Refresh material choices when the server reports stale evidence. Use the runtime schema for geometry limits.
6. If the response says `awaiting_upload`, save its JSON to a private temporary ticket file and run `python scripts/upload_stl.py upload /absolute/path/part.stl --ticket /absolute/path/ticket.json`. The helper PUTs the original bytes using the returned headers. Keep the signed URL out of chat and repositories. Delete the ticket after transfer.
7. Call `complete_stl_upload` with `projectId` and `uploadId`. If preparation already says `completed`, proceed directly to this call. If a PUT response is uncertain, try completion before starting another upload.
8. Check the returned mesh preparation status. If unavailable, report the saved part and retry completion; do not claim a visible mesh or start packing from an unprepared import. Show dimensions, measured weight, material, cost with its source, volume and retained checksum. Use the final `modelId` and revision in `prepare_proposal` with the selected containers.

The server verifies file identity and geometry, retains the STL, and prepares the mesh through the same source pipeline as website uploads. Material selection does not replace measured mass. Invalid geometry needs correction or a website import path. For an expired reservation use a new idempotency key. Reuse an upload ID after an uncertain completion response to avoid duplicate parts.

If cleanup has removed the reservation after a completed import, discover the saved part in `get_project_context` before starting another import.
